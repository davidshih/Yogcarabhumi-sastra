6. 技術細節附錄

設計與理由（id 格式、存放）

格式 <段落誕生時所屬 section 的 Range 起點>-<6 hex>，例 T30n1579_p0281b03-997ff5。hex = sha1(section 起點 + 當時譯文) 前 6 碼，只在第一次指派時算，撞到同頁已用 id 就加 salt 重算（實測 21 個 block 內有完全相同的重複段落）。

存放在 translations/*.md 的 Translation: 區塊，每段第一行一個 HTML comment marker（GitHub 預覽看不到）。理由：人手拆段時 marker 自然跟著前半段；sidecar 則每次 build 都要模糊對齊。runner 的 LLM 輸出沒有 marker，所以 splice() 用 difflib 對齊新舊段落沿用 id；parse_entries() 會剝掉 marker，prompt 與搜尋索引不受影響。render() 遇到沒 id 的段落直接 raise，保證發佈頁不會漏。
