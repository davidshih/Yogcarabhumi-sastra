## Decisions
- Two pipelines, not one merged runner. The two runners grew apart from a 689-line ancestor (`372a274`, 2026-07-05) into different protocols (text markers against JSON contracts). A merge of the two files would be a rewrite that no test of either side covers. The production runner stays as it is; the audited runner is a second entry point.
- Juan 67–72 on `main` stay as legacy pages. The branch deleted them because its strict checks fail on them (glossary issues, shared boundary lines). The audit command is the way to bring a published juan under the audit trail without translating it again.
- The legacy audit seals the files of one juan and the artifacts of its job (requests, answers, the passed candidate, the glossary, the policy and the prompts as they were). It does not seal `search.json`, the index pages or the live glossary: the next juan changes them.
- A failed attempt of the audit puts the translation, its page and the search indexes back, also when a kill came between two attempts. The page comes from a snapshot in `audits/<job>/backup/<n>-site/`. A later attempt builds the search indexes again from the md instead of writing the old snapshot back, because another job may have published a juan meanwhile; it does that only when the translation went back, so no candidate is indexed.
- The only step that puts a file at the path of a translation is a hard link. It is atomic and never replaces a file. A copy (tried in the first fix round) can leave half a file after a kill; a rename can replace a newer save. So when the link fails, nothing is written: the file waits in the backup folder and the job keeps its record.
- The last check of an audit reads the glossary, the policy and the prompt files once and pins them. Every prompt of that check, the ledger, the content checks and the gate use the pinned bytes, and the gate stores them. A change of those files after the pin is not part of that audit.
- 已翻 = `docs/<work>/translations/<work>-NNN-baihua.html` exists (readable page), not "Markdown has text". Drafts exist mid-job, and parsing ~40 MB of Markdown on every `save_job()` is too slow.
- 進行中 = the juan is in a job whose state is not done/failed/cancelled, its step is not done/cancelled/**commit**, it is not flagged cancelled, and it has no task in state `failed`. Step `commit` counts as published because `git_commit_push()` pushes the page before `mark_juan_done()` runs. Otherwise the last juan of every job would show 進行中 online forever (Codex review finding #1).
- A work without `juans` falls back to the highest juan seen on disk or in active jobs.
- Output paths derive from `STATUS_JSON.parent`, never `ROOT`: the existing tests patch only `STATUS_JSON` and call `save_job()`, and a `ROOT`-based path would let them overwrite the real page.
- The rail stays the site's own; only the content column uses the 追更簿 look. The page links `style.css?v=20260930` (other pages still use `?v=20260711`).

- Paragraph id format: `<section Range start at birth>-<6 hex>`, for example `T30n1579_p0281b03-997ff5`. The hex is sha1 of the section start and the paragraph text, computed once when the id is assigned, and salted when the id is already used on the page (21 blocks hold identical paragraphs). The `-` cannot occur in a CBETA section id or a fixed UI id, so there is no collision. `id.rsplit("-", 1)[0]` gives the section where the paragraph was born, a fallback anchor for the app.
- Paragraph id storage: one HTML comment line (`#` plus the id) as the first line of each paragraph in a `Translation:` block. A hand split keeps the marker on the first part; a merge keeps the first marker. A sidecar file was rejected: it needs fuzzy re-alignment on every build. `build_page()` adds missing ids and writes the md back; `render()` raises when a paragraph has no id, so the runner cannot publish a page without ids.
- Runner rewrites: LLM output has no markers. `splice()` calls `carry_paragraph_ids()`, which aligns old and new paragraphs with difflib; equal and replaced runs keep their ids in order, inserted paragraphs get a new id at the next build. `parse_entries()` removes the markers, so prompts never see them.
- No codex-pipeline run for this thread: the user wanted it unattended without questions. Gates were TDD tests, a full byte diff and browser checks.

## Gotchas
- `scripts/audited.py audit` without `--model echo` calls the real Codex backend and spends quota. It writes `audits/`, `artifacts/`, `jobs/audited/` and, for a juan that passes, the md, its page and every `docs/*/search.json`. Run it on a branch of its own, never on `main`, and never as an experiment in the main checkout. The offline backends are `echo` (every review passes), `echo-finding`, `echo-finding-stubborn` and `echo-finding-merge`.
- The audit command needs a filesystem with hard links. Without them it refuses the install before it moves the translation (`no hard link can be made here`).
- Known limit C4-1 (accepted by the owner, 2026-10-14): if `docs/T1579/search.json` does not exist when an audit starts, and a kill comes after the rebuild, and the resume fails, and the original cannot be linked back, the records of the candidate stay in the new index. Do not delete `docs/T1579/search.json` before an audit. A 4-line fix is described in `plans/20261013-merge-audit-pipeline-claude/acceptance-result.md` (C4-1).
- When a hard link fails after the translation moved (an I/O error), the command ends with the path of the translation empty. The report line names the file (`the translation is in audits/<job>/backup/<n>-<name>: it could not go back to its path`), and `python3 scripts/audited.py audit --resume <job id>` puts it back. Do not copy it back by hand while a job is running.
- `audits/` and `artifacts/` are not in `.gitignore`: they are the audit trail and are committed with the audited juans. `jobs/` and `locks/` are ignored.
- A merge to `main` of this repo must use a merge commit when the branch carries a merge of another branch (a squash loses the second parent). The repo has no linear-history rule.
- A full reprocess of a juan (archive the md, build a fresh skeleton) re-translates from scratch and gives that juan new paragraph ids. The archived version page keeps the old ids.
- `HANDOFF.md` must not contain an HTML comment, so do not paste a marker line here.
- `.gitignore` ignores raw codex-pipeline reviewer logs (`plans/*/*.log`, `plans/*/*.log.out`, `plans/*/diff.reviewed-tree`) since 2026-10-06. The curated `*.md` reviews stay tracked.
- Actions must be pinned to a full commit SHA (`sha_pinning_required`), also inside composite actions. Write a new action as `owner/action@<40-hex> # vX.Y.Z`, and check its `action.yml` for nested `uses:` by tag.
- `docs/status.json` here is the runner's job status, published on Pages and read by `status.html`. Do not overwrite it with the global handoff `status.json` template; this repo is an exception to that rule.
- The online page is only as fresh as the runner's last push. A job that ends cancelled / failed / held after its last pushed juan leaves stale 進行中 cells on Pages until the next runner commit. `docs/status.json` already behaves the same way. To refresh by hand, run the command below, then commit and push.
- `qtest` does not work in this repo: it runs a global pytest on an older Python, which fails on the PEP 701 f-string at `scripts/build_translation_html.py:366`. Use `python3 -m unittest discover -s tests` (Python 3.14).
- `works.json` metadata has drifted: T1558 still says `pipeline_ready: false` with 30/30 juans done; T1579 `scope: 聲聞地`, but translations cover 1–12 and 51–80 too. Not changed.
