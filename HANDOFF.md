## Decisions
- 已翻 = `docs/<work>/translations/<work>-NNN-baihua.html` exists (readable page), not "Markdown has text". Drafts exist mid-job, and parsing ~40 MB of Markdown on every `save_job()` is too slow.
- 進行中 = the juan is in a job whose state is not done/failed/cancelled, its step is not done/cancelled/**commit**, it is not flagged cancelled, and it has no task in state `failed`. Step `commit` counts as published because `git_commit_push()` pushes the page before `mark_juan_done()` runs. Otherwise the last juan of every job would show 進行中 online forever (Codex review finding #1).
- A work without `juans` falls back to the highest juan seen on disk or in active jobs.
- Output paths derive from `STATUS_JSON.parent`, never `ROOT`: the existing tests patch only `STATUS_JSON` and call `save_job()`, and a `ROOT`-based path would let them overwrite the real page.
- The rail stays the site's own; only the content column uses the 追更簿 look. The page links `style.css?v=20260930` (other pages still use `?v=20260711`).

## Gotchas
- The online page is only as fresh as the runner's last push. A job that ends cancelled / failed / held after its last pushed juan leaves stale 進行中 cells on Pages until the next runner commit. `docs/status.json` already behaves the same way. To refresh by hand, run the command below, then commit and push.
- `qtest` does not work in this repo: it runs a global pytest on an older Python, which fails on the PEP 701 f-string at `scripts/build_translation_html.py:366`. Use `python3 -m unittest discover -s tests` (Python 3.14).
- `works.json` metadata has drifted: T1558 still says `pipeline_ready: false` with 30/30 juans done; T1579 `scope: 聲聞地`, but translations cover 1–12 and 51–80 too. Not changed.
